Копирование записей и страниц между сайтами сети WordPress Multisite.

== Description ==

Copy Post переносит записи, страницы и включённые произвольные типы записей с текущего сайта сети на другие сайты этой же сети.

Что переносится:

* заголовок, контент, отрывок, слаг, статус, дата, автор;
* родительская страница, порядок, шаблон страницы, формат записи, закрепление;
* таксономии: категории, метки и произвольные таксономии с сохранением иерархии;
* выбор таксономий отдельно для каждого целевого сайта: скопировать с источника, выбрать существующие термины на цели или не копировать; при необходимости можно создать новый термин прямо в окне копирования;
* произвольные поля (мета), кроме служебных;
* медиа: миниатюра и файлы, на которые ссылаются контент и мета; файлы копируются в uploads целевого сайта, ID и URL перепривязываются;
* комментарии — по желанию;
* ссылки исходного сайта переписываются на целевой.

Плагин запоминает связь между оригиналом и копией. Это позволяет:

* видеть, куда уже скопирована запись;
* обновлять существующую копию вместо создания дубля;
* открывать источник и копии из админки.

== Installation ==

1. Установите плагин в `wp-content/plugins/copy-post`.
2. Активируйте его для всей сети: **Сеть → Плагины → Активировать для сети**.
3. Настройте параметры: **Сеть → Настройки → Копирование записей**.
4. На любом сайте сети откройте **Инструменты → Копирование записей** или используйте действие «Копировать на сайт…» в списке записей.

Плагин работает только в WordPress Multisite. На одиночной установке он показывает уведомление и не загружает интерфейс.

== Usage ==

**Быстрое копирование одной записи**

В списке записей или страниц наведите курсор на запись и выберите «Копировать на сайт…». В окне отметьте целевые сайты, выберите состав данных, поведение при существующей копии и статус. Нажмите «Копировать».

**Массовое копирование**

Выделите несколько записей в списке и выберите массовое действие «Копировать на сайт…». На странице подготовки проверьте список, выберите сайты и параметры, затем запустите копирование.

**Отдельная страница**

**Инструменты → Копирование записей** позволяет отфильтровать записи по типу, статусу и поиску, выделить нужные и скопировать их на несколько сайтов.

**WP-CLI**

`wp copy-post sites` — список сайтов сети.

`wp copy-post posts --site=2 --post-type=post` — список записей сайта.

`wp copy-post copy 123 --to=2 --status=draft` — скопировать запись 123 на сайт 2.

`wp copy-post copy 123 --to=2,3 --duplicate=update` — обновить существующие копии на сайтах 2 и 3.

== Frequently Asked Questions ==

= Нужен ли доступ к базе данных или FTP? =

Нет. Плагин работает через API WordPress и `switch_to_blog()` внутри сети. Файлы медиа читаются из `uploads` исходного сайта и записываются в `uploads` целевого.

= Копируются ли изображения? =

Да, если включён пункт «Медиа». Копируются миниатюра и файлы, на которые ссылаются контент и мета. Для каждого файла создаётся отдельное вложение на целевом сайте, размеры генерируются заново под тему целевого сайта. Повторно один и тот же файл не загружается.

= Что будет с ссылками на исходный сайт? =

Домен, `site_url` и URL скопированных файлов заменяются на целевые. Ссылки на другие записи исходного сайта получат домен целевого сайта; если таких записей на цели нет, они будут вести на 404 — скопируйте связанные записи пакетом.

= Как обновляется копия? =

В окне копирования выберите «Обновить существующую». Плагин найдёт копию по сохранённой связи и обновит её, сохранив ID и ссылку. Слаг по умолчанию не меняется; это можно включить в настройках сети.

= Как выбрать другие рубрики и метки на целевом сайте? =

В окне копирования выберите целевой сайт, затем в разделе «Таксономии на целевых сайтах» переключите режим на «Выбрать на сайте». Плагин загрузит существующие таксономии и термины именно этого сайта. Отметьте нужные рубрики, метки или произвольные термины. Для каждого сайта настройка своя: можно одному сайту скопировать таксономии с источника, другому — выбрать вручную, третьему — не копировать.

Если нужного термина на цели ещё нет, введите его название и нажмите «Создать» — термин будет создан и сразу выбран. Для иерархических таксономий можно указать родительский термин.

= Что делает галочка «Очищать невыбранные таксономии»? =

Она действует только в режиме «Выбрать на сайте». Если галочка стоит, таксономии без выбранных терминов будут очищены (для рубрик — назначена рубрика по умолчанию сайта). Если снять — невыбранные таксономии останутся как на целевом сайте, что удобно при обновлении копии.

= Почему целевой сайт не отображается в списке? =

Пользователь должен быть участником целевого сайта и иметь право, указанное в настройках (по умолчанию `edit_posts`). Супер-админ сети видит все сайты. Архивные, спам- и удалённые сайты скрыты.

= Копируются ли комментарии? =

По умолчанию нет. Если включить, они копируются только при создании новой копии; при обновлении новые комментарии не синхронизируются.

= Поддерживаются ли page builders? =

Мета копируется как есть. Для Elementor, Divi и аналогичных конструкторов может потребоваться их собственный импорт или фильтр `copy_post_meta_value`. Блоки Gutenberg, включая изображения и галереи, поддерживаются.

= Что будет при удалении плагина? =

Записи и медиафайлы не удаляются. По умолчанию служебная мета связей тоже остаётся. Очистку можно включить в настройках сети.

== Hooks ==

`copy_post_payload` — изменить данные перед вставкой копии.

`copy_post_content` — изменить контент после перепривязки медиа и ссылок.

`copy_post_meta_value` — изменить значение мета-поля при копировании.

`copy_post_before_insert` — действие перед вставкой/обновлением.

`copy_post_after` — действие после успешного копирования.

`copy_post_sites_limit` — ограничить число сайтов в списке (по умолчанию 500).
